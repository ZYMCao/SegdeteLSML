# 主循环行为契约

本文件记录主循环的兼容要求和本次明确采用的调度规则。响应测试中的秒数是测试容差，不是生产 SLA。

## 修改间隔

- 间隔接受非负整数及其十进制字符串。0 保留连续采集语义；负数、布尔值和浮点数不合法。
- 启动配置和命令使用同一校验函数。不合法的命令只记录错误，保留原间隔，不发送成功确认；不合法的启动配置拒绝启动。
- 新间隔立即作用于当前等待，以最近一次检测完成时间为起点，不以收到命令的时间重新计时。
- 新截止时间已过，处理待办命令后即可开始下一轮。
- 例如上一轮在 t=0 完成，t=25 将间隔从 60 改为 40，下一轮在 t=40 开始；改为 10 则在 t=25 开始。
- 暂停后恢复立即允许采集；同一批命令修改间隔不延迟恢复后的第一轮。
- 自动验证：`test_processor_schedule.py` 使用可控时钟检查准确时间点，真实线程唤醒由 `test_processor_commands.py` 覆盖。

## 正常采集节奏

- 保留原有固定延迟语义：本轮完成后等待 interval，再开始下一轮，不按本轮开始时间计算。
- 使用单调时钟；截止时间是允许采集的最早时间，线程繁忙可以更晚，不能更早。
- 例如 interval=10，各轮耗时依次为 7、25、2 秒，开始时刻应为 0、17、52。
- 曝光、帧率命令以及重复的“保持运行”命令，不得提前或推迟下一次采集。
- 同步检测期间到达的命令，在检测完成后处理；命令处理不会额外增加一个采集间隔。
- 命令按 FIFO 处理，每批有数量上限；持续到来的命令不能无限推迟已经到期的采集。批次之间检查退出和采集截止时间。
- 自动验证：`test_processor_schedule.py` 精确检查开始时刻以及命令确认顺序。
- `test_processor_fairness.py` 持续补充命令，验证采集仍能发生且确认顺序不变。

## MQTT 命令入口

- 一条属性更新消息中的每个属性只入队一次。SDK 的按键订阅回调会收到整份消息，因此使用一个整体属性订阅，避免批量更新被重复分发。
- 成功确认使用对应的实际命令处理结果；无效输入、未知命令、设备失败不发送成功确认。
- 自动验证：`test_mqtt_commands.py` 使用真实 Paho 消息对象、ThingsBoard SDK 解码/分发、业务适配器、队列和处理循环；只替换网络连接/发送与设备、模型。它不是 broker 端到端测试，也不承诺 MQTT 重投消息的业务去重。

## 退出

- CLI 和调用主循环的代码使用 `ShutdownEvent(commands)`，调用 `set()` 同时设置退出标记并唤醒命令等待；调用方无需另发唤醒消息。
- SIGTERM、Ctrl+C 均走同一退出事件。
- 开启 Web 时，同时停止预览线程并请求 Uvicorn 退出；主线程等待资源释放完成。
- 等待和暂停中的处理线程应结束，并释放相机资源。
- 正在执行的同步抓图、推理无法被事件强制中断，完成后检查退出标记。
- 自动验证：`test_processor_commands.py` 的退出用例，以及 `test_cli_shutdown.py` 的真实子进程信号测试（运行/暂停 × SIGTERM/SIGINT × Web 开/关）。子进程显式导入当前源码；Web 测试在本机随机端口启动真实 Uvicorn。信号测试替换硬件和模型，不代表实机验收。

## 启动与降级

- 预热逐帧执行，在帧间处理命令。暂停期间不继续抓图；恢复后完成剩余预热，再开始检测。
- 无相机时不加载处理模型、不采集，但仍接受运行状态和间隔命令；曝光命令不返回成功确认。
- 初始化异常和预热中退出均释放相机资源。已经开始的模型初始化、SDK 抓图仍是同步调用，命令无法中断它们。
- 自动验证：`test_processor_startup.py` 检查初始暂停、预热中暂停/退出、无相机，以及初始化失败清理。

## 相机命令

- 运行状态只在相机启动/停止调用成功后更新；调用失败保留原状态，不发送成功确认，继续处理后续命令。
- 任一相机曝光设置失败，不发送成功确认。可能已有另一台相机应用新值；这里不承诺硬件事务回滚。
- 重复暂停/恢复保持幂等，不重复调用相机启动/停止。确认回调抛异常和未知命令不得终止消费者。
- 自动验证：`test_processor_failures.py` 注入 SDK 失败和确认异常，检查状态、确认顺序以及后续命令处理。
- 曝光和增益设置在读取设备范围时允许同一线程重入相机锁，同时继续排斥其他线程访问设备。
- 保留按设备范围裁剪输入的行为。
- 自动验证：`test_camera_controls.py` 调用真实相机管理器和线程，仅替换底层相机 SDK 节点。

## 检测结果

- 一轮成功处理写出左右原图、全景图、CSV 和包含图像标识及 URL 的遥测；启用检测时还写检测可视化。
- 抓图不足或拼接无结果时，不写 CSV、不发送成功结果遥测。
- 中间图像由拼接模块持有，处理函数不能引用已不在自身作用域的预对齐、校正变量。
- 自动验证：`test_processor_cycle.py` 调用真实处理函数与 OpenCV 图片/CSV 写入；相机、拼接和推理输入使用替身。
- 其中 `test_cycle_with_configured_model_weights_on_cpu` 使用配置解析出的真实权重执行 CPU 推理及输出。输入是合成图，只验证集成链路，不评价模型精度；没有权重时明确标记跳过。
